# 예스랭귀지 → C 포팅 규약

## 목표

예스랭귀지 원본과 C 코드가 서로 이해 가능한 형태로 유지되는 플랫폼을 만든다. 원본이 놓인 폴더 이름을 C 포팅 폴더 이름으로 그대로 쓴다. 내용으로 다시 나누어 다른 폴더에 넣지 않는다.

| 종류 | 원본 (reference/yeslanguage/) | C 포팅 (src/core/) |
|---|---|---|
| 함수 | `functions/` | `functions/` |
| 지표 | `indicators/` | `indicators/` |
| 시그널 | `signals/` | `signals/` |
| 전략 | `strategies/` | `strategies/` |

새 원본은 처음부터 원본 종류와 같은 폴더에 둔다. `signals/`의 시스템 원본은 매매 명령이 있어도 `signals/`에 둔다.

## 타입 판별 규칙

원본에 폴더가 있으면 그 폴더가 종류다. 폴더 없이 도착한 파일만 내용으로 폴더를 정한다.

- 매매 명령(Buy/Sell 계열)이 있으면 **시그널** (`signals/`)
- `PlotN()` 출력이 있으면 **지표**
- 둘 다 없고 타입 인자(`Input Numeric`/`NumericRef` 등)만 있으면 **함수**

애매하면 추측하지 않고 사용자에게 묻는다.

## 포팅 규약

- 파일은 1:1로 대응한다: `WSF_X.txt` ↔ `x.c` / `x.h`
- 원본 변수명을 그대로 유지한다
- 주석에 원본의 행 번호·섹션을 인용한다
- `Input` 인자 → config 구조체
- `OUT`/`ref` 인자 → 출력 구조체 또는 페이로드
- 불명은 추측 금지: 모르는 동작은 임의로 만들지 않고 불명으로 기록한다
- 단위 테스트에는 실측 기대값(손계산 또는 HTS 실측)을 둔다

## 암묵 시계열 원칙

예스랭귀지의 변수는 모두 시계열이다(봉마다 값이 쌓이고 `[n]` 참조가 가능). C에서는 이 '변수'를 표현하는 통일 타입 `yl_var`(src/core/market/var.h — 검증된 `tr_ring`의 double 전용 얇은 래퍼)로 재현한다. 인덱스는 최신 기준 상대값([0]=현재)이고, 가득 차면 가장 오래된 값을 덮어쓴다. 저장소는 호출자 소유이며 상태 구조체 안에 버퍼를 둔다.

| 예스랭귀지 | C (yl_var) |
|---|---|
| 변수 선언 `var x;` | `YL_VAR_STORAGE(x, cap);` + `ylv_init(&x, x_buf, cap);` |
| 대입 `x = expr;` (매 봉 1회) | `ylv_push(&x, expr);` |
| 같은 봉 내 재대입 | `ylv_set_current(&x, expr);` (과거를 밀어내지 않고 [0] 제자리 교체) |
| 참조 `x[N]` ([0]=현재) | `ylv_at(&x, N, &out)` — 범위 초과 시 false |

- 살아있는 규약 예시: `tests/test_var.c`의 `test_yeslanguage_1to1_example` (예스랭귀지 스니펫과 같은 값을 냄)
- 파일럿 전환: `src/core/functions/atr.c`의 SMA 이력(`sma_hist`)이 yl_var로 구현되어 있다

**값 복사 불안전 제약**: 저장소 버퍼를 상태 구조체 안에 두는 이 규약은 값 복사 불안전 타입을 만든다 — yl_var를 포함한 구조체를 통째로 값 복사(이식 등)하면 사본의 `ring.storage`가 원본의 버퍼를 가리키는 채로 남아, 원본 슬롯이 재사용될 때 두 상태가 버퍼를 공유하며 조용히 깨진다. 통째 복사 후에는 반드시 재연결 헬퍼로 사본 자신의 버퍼로 저장소 포인터를 복구한다: 범용 `ylv_relink(&s, new_buf)` 또는 모듈별 래퍼(예: `tr_atr_relink(&a)`). 적용 사례: `tr_engine_pipe_remove`의 파이프라인 이식(src/runtime/engine.c)과 회귀 테스트 `tests/test_engine.c`의 `test_pipe_transplant_atr_relink`. 후속 yl_var 전환에서도 같은 검토가 필요하다. 예외: score_1m의 `mid_hist`처럼 저장소를 외부(호출자 소유 버퍼)에서 부착받는 경우는 기증 슬롯을 가리키지 않으므로 relink가 필요 없다.

### 전환 기준 (무엇을 yl_var로 하는가)

- **전환한다** — 예스랭귀지 '변수'(암묵 시계열)에 1:1로 대응하는 double 이력: atr의 TR 이력, obd2의 핵심점수·계산호가방향, lp4의 회귀기울기입력 이력, htf의 (L+H)/2 이력, lr3의 회귀가격, sma의 종가 창, gap1의 완성 세션 TR, dtl1의 완성 일봉 중간값, score_1m의 핵심마켓 (H+L)/2.
- **두는 것 ① 스칼라/[1] 깊이 재귀** — 직전 값 1개만 기억하는 갱신은 시계열 타입 없이 스칼라 필드로 둔다 (adx1, memory_lines의 prev 계열, score_1m의 prev_future_dir/prev_market_center).
- **두는 것 ② 무상태** — 이력 자체가 없는 순수 계산은 해당 없음 (linreg.c의 OLS, daily_align_v2, daily_linreg_trend_v1).
- **두는 것 ③ 캔들/프레임 링** — 예스랭귀지 '변수'가 아니라 내장 가격·거래량 시리즈 윈도우(캔들 링)나 복합 프레임(예측가+신뢰도+방향+유효) 이력은 double 전용 yl_var로 분해하면 충실도를 해치므로 기존 구조를 유지한다 (market_profile, daily_market_profile_v1, past_prediction).
- **두는 것 ④ 정수 키 이력** — 값의 시계열이 아니라 비교 키(일자 경계 등)인 정수 이력은 정수 배열 그대로 둔다 (linreg_predict_v4의 day_hist — yyyymmdd < 2^53이라 double 표현은 가능하지만 타입 마찰 회피).

## HTS 고유 동작

HTS(예스랭귀지 실행 환경) 고유의 동작은 하나씩 동일하게 구현하고, 구현한 내용과 불명 항목을 [docs/yeslanguage_mapping.md](yeslanguage_mapping.md)에 기록한다. 플롯이 화면에 이어지는 방식과 대시보드가 그 화면을 흉내 내는 규칙은 아래 「화면 시각화」에 둔다.

## 화면 시각화

계산과 그리는 방법을 나눈다. 엔진은 예스랭귀지와 같은 숫자를 낸다. 예스랭귀지 원본은 화면을 맞추려고 고치지 않는다. 수식에 도형 문장이 없어도, 사용자가 대시보드에 지정한 그리기는 구현한다.

마커 모양은 수식, 확인된 차트 속성, 또는 사용자가 지정한 것만 안다. 색이 비슷하다고 십자나 원을 붙이지 않는다. 표시 실험에서 십자와 원이 어느 플롯인지는 아직 닫히지 않았다. 기록은 [reference/yeslanguage/experiments/표시실험1_리포트.md](../reference/yeslanguage/experiments/표시실험1_리포트.md)의 「십자와 동그라미는 아직 모른다」.

### HTS `Def`로 확인된 이음

`Def`는 점선이 아니다. 0과 100 밖의 값도 그 자리에 그린다.

- 봉마다 값이 같으면 가로 실선이다.
- 값이 한동안 같다가 다음 봉에 크게 바뀌면, 이전 가로의 끝에서 새 색의 수직선이 새 값에 닿고 이어서 새 굵기의 가로가 된다.
- 봉마다 값이 조금씩 바뀌면 한 사선이다. 색이 바뀌어도 수직으로 꺾지 않고 그 사선 위에서 색만 바뀐다.
- 몇 봉을 쉬고 다음 값이 다르면 빈칸으로 지우지 않는다. 이전 점에서 다음 점까지 새 색의 사선으로 잇는다.

이 이음은 HTS 기본 플롯의 관찰이다. 대시보드의 미래곡선·스나이퍼는 아래에서 따로 그린다.

### 대시보드 공통

구현은 `web/public/horiz-lines.js`다. 차트 라이브러리 선은 끄고(`lineVisible: false`) 프리미티브가 그린다. 라이브러리 기본 선은 한 스타일이라, 봉마다 색과 굵기가 바뀌는 선을 그리지 못한다.

| 함수 | 그리는 것 |
|---|---|
| `primitive` | 같은 값이 이어진 구간만 수평. 값이 바뀌거나 봉이 비면 끊는다. 한 봉은 짧은 토막이다. |
| `flat` | 이웃 봉의 값과 색이 같을 때만 수평. |
| `segments` | 이전 표시 점에서 이번 점으로 직선. 색과 굵기는 이번 봉. 각도가 보이게 잇고, 수직 다음에 수평으로 꺾지 않는다. |
| `plus` | 채운 선 없이 +. 팔 길이는 3 CSS px. |
| `dots` | 채운 원. 지름은 그 점의 `width`. 원끼리는 잇지 않는다. |
| `arrows` | 값이 있는 봉마다 채운 삼각형. `up`은 값 위, `down`은 값 아래. |

비트맵 좌표로 긋는 선의 굵기는 `width * verticalPixelRatio`다. 미디어 좌표(V3 미래 광선, 국내 V16 선분)의 굵기는 CSS px다.

라이브 틱은 이력 전체를 `setData`로 다시 깔지 않는다. 미래곡선 V1·V3와 스나이퍼 Data2는 마지막 봉만 `update`한다. 같은 종목의 같은 봉 틱은 마지막 것만 남겨 프레임당 한 번 그린다(`web/public/app.js`의 `liveQueue`). 봉이 바뀐 메시지는 순서를 지킨다. 전체를 다시 깔면 마커가 늘수록 한 틱이 다음 틱보다 길어지고, 차트 시각이 서버보다 뒤로 밀린다.

분봉 목록은 없음, 캔들바, 테두리, 바, 종가선이다. 테두리는 몸통을 비운 캔들이고 테두리만 2 CSS px다. 속을 채운 캔들의 테두리는 1px이다. 분봉이 없음이면 그 칸의 가격 눈금은 raw 숫자를 찍는다. 캔들 칸은 100으로 나눈다. 눈금 포맷터는 칸마다 하나다.

### 해외 미래곡선 V1

`web/public/fx-layers.js`. 단계색은 점수 기준이다.

| 점수 | 색 |
|---|---|
| ≥ 4 | `#dc0000` |
| ≥ 2 | `#ff6446` |
| 1 | `#ffb9b9` |
| 0 | `#969696` |
| −1 | `#b4d2ff` |
| ≤ −2 | `#3c82ff` |
| ≤ −4 | `#0000b4` |

- 점수와 그 밖 지속·합성 선은 수평으로 끊는다.
- 회귀선만 `segments`다. 색은 이번 봉의 단계색, 굵기는 R² ≥ 0.70이면 6, ≥ 0.40이면 4, 그 외는 2다. 수식 Plot2의 굵기 3은 대시보드에서 쓰지 않는다. 값은 수식 그대로다.
- 마켓중심은 값과 단계색이 같은 이웃만 수평이다. 굵기 3. 회귀선처럼 사선으로 잇지 않는다.
- 지난상승·지난하락의 고가·저가는 봉마다 +다. 0.382, 0.5, 0.618 여섯 플롯은 그리지 않는다.

### 해외 미래곡선 V3

`web/public/fx3-layers.js`.

- Plot7 회귀선은 `segments`다. 색과 굵기는 그 봉 페이로드의 rgb, width다.
- 그 밖 선은 `flat`이다.
- 스윙 고저 Plot60, 61, 65, 66은 +다. 0.382, 0.5, 0.618인 Plot62–64, 67–69는 그리지 않는다.
- 미래목표선과 미래범위는 직전 봉 시각에서 칸의 오른쪽 끝까지 수평이다. 차트 전체를 가로지르지 않는다. 범위의 폭 계산은 `max(잔차, 변동성×0.25) × sqrt(예측봉수)`다. 기울기 부호로 범위를 회색으로 바꾸지 않는다.

목표선 색은 그 구간의 방향이다. 상승, 하락, 보합 순이다.

| 구간 | 굵기 | 상승 | 하락 | 보합 |
|---|---|---|---|---|
| 0 | 1 | `#ff9191` | `#91aaff` | `#a0a0a0` |
| 1 | 3 | `#ff0000` | `#0000ff` | `#828282` |
| 2 | 1 | `#cd3737` | `#3755cd` | `#a0a0a0` |
| 3 | 2 | `#cd3737` | `#3755cd` | `#a0a0a0` |
| 4 | 3 | `#cd3737` | `#3755cd` | `#a0a0a0` |

범위선 굵기는 1이다. R² < 0.40이면 모두 `#b4b4b4`다. 그 외 구간 0은 `#bed2be`, 구간 1은 `#a5a5a5`, 구간 2–4는 `#cdc3cd`다.

### 국내 미래곡선 V16

`web/public/mirae-layers.js`. 회귀선과 마켓중심은 해외와 같은 이음이다.

- 회귀선 선분의 색은 이번 봉 점수색(`scoreColor`), 굵기는 이번 봉 R²(`regWidth`)다. 직전 봉 스타일을 이 선분에 칠하지 않는다.
- 마켓중심은 값과 점수색이 같은 이웃만 수평, 굵기 3이다.
- 국내 점수색 경계는 수식과 같이 `> 4`, `> 2`, `> 0`, `< −4`, `< −2`, `< 0`이다. 해외 V1의 `≥ 4`와 경계가 다르다.

`첫이탈`은 목표 폭이 유지되는 한 구간에서 처음 벗어난 봉에만 켜진다. 화면은 그 다음 봉이다. 같은 폭에서 들어갔다 다시 벗어나도 화살표는 다시 나오지 않는다. 세션 첫 봉과 삼선 목표 미준비는 숨긴다. 페이로드는 `ymae` 배열 14번 `show_first`다. 6번 `h1`은 가설1이라 화살표 조건이 아니다.

Plot21 수평선 위에 화살표를 겹치지 않는다. 화살표는 Plot22·23만이다. 가격압축, 복합압축, 상단유지, 하단유지는 수평이다.

삼선비율 눈금은 값이 한곳에 몰려도 최소 −20과 120을 포함하게 잡는다(`autoscaleInfoProvider`). 원의 세로 위치가 HTS와 같다는 확인은 아직 없다.

신호점 Plot29와 비율점수 강조 Plot30은 삼선비율 높이의 채운 원이다. 위는 파랑 반지름 4, 아래는 빨강, 동시는 초록이다. 강조는 빨강 계열 노랑, 파랑 계열 시안, 녹색 흰색이고 반지름 2다.

### 화면에서 아직 열린 것

- 칸의 세로 시간 가이드는 오른쪽 끝 시각과 px 봉 간격을 같게 맞춘다. 봉이 1개뿐인 칸의 창을 기준으로 삼지 않는다. `setVisibleLogicalRange`는 다음 프레임에 반영되므로 같은 턴에서 다시 읽지 않는다. 새로고침 뒤 화면틀을 열면 가끔 칸마다 어긋나는 경우가 남아 있다.
- 삼선비율 숫자는 Data2와 같고, 원의 화면 높이가 HTS와 같다는 것은 확인 전이다.

## 변경 동기화 절차

원본은 git 관리가 원칙이다(투입·변경 시 커밋 먼저).

1. 변경 감지: `git diff` + SOURCE_INDEX의 SHA-256 해시 대조
2. diff 범위만 C 모듈과 테스트를 갱신한다
3. `ctest`로 검증한다
4. 해시를 SOURCE_INDEX에 재등록한다
5. 원본과 C를 같은 커밋으로 묶는다

큰 구조 변경은 작업 전에 영향 범위를 먼저 보고한다.
